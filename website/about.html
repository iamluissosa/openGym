Acerca de balackGym

balackGym no fue planeado como un producto. Comenzó como una pequeña aplicación que construí para un único usuario: yo.

Buscaba tres cosas en el gimnasio: registrar mis entrenamientos, seguir mi peso corporal y comprobar si progresaba. Todas las aplicaciones que probé exigían suscripción, una cuenta obligatoria o mis datos en servidores de terceros — normalmente las tres cosas. Así que hice lo propio de un entusiasta del homelab: construí una pequeña web móvil, la subí a mi propio servidor y empecé a registrar.

Resulta que una herramienta que diseñas para ti mismo se pule de una forma en que los productos comerciales no lo hacen. Cada interacción incómoda frente a la jaula de sentadillas se convertía en el arreglo de esa misma noche. El flujo de entrenamiento guiado, el autorrelleno de pesos, el cronómetro de descansos y el ritual de anotar el peso antes de la primera serie surgieron de la experiencia real en la sala de pesas con el teléfono en la mano.

Después, mis amigos quisieron unirse. Eso motivó los perfiles con passkey — inicia sesión con huella dactilar, sin contraseñas y con datos separados — y la sincronización entre dispositivos. Con el tiempo, la pequeña página evolucionó a una aplicación React completa, incorporó 12 idiomas, un mapa muscular, importadores para FitNotes, Strong, Hevy y Apple Health, y finalmente una app nativa Android disponible directamente desde esta web.

En julio de 2026 liberé el código bajo licencia AGPL. La licencia es la esencia, no un detalle menor: tus datos deben ser tuyos, el software que los gestiona debe ser auditable y nadie — incluyéndome a mí — debe poder arrebatarle una versión cerrada o de pago a la comunidad.

balackGym sigue ejecutándose en el mismo servidor homelab donde nació, y sigo registrando cada sesión con él. Ese es el estándar de calidad: soy el primer usuario de cada versión.

— balackGym

Principios

  • Tus datos te pertenecen. Local-first, respaldos en un solo archivo, sin cautiverio — salir de balackGym siempre estará a una exportación de distancia.
  • Cero telemetría, siempre. Si una función necesita analíticas para justificarse, no se incluye.
  • Mínimas dependencias. El backend es un único archivo Node con una sola dependencia; el frontend es React, un router y un almacén de estado. Lo bastante conciso como para ser auditado.
  • Código abierto que sigue abierto. AGPL-3.0, de modo que cada bifurcación y versión alojada debe compartir su código con la comunidad.
